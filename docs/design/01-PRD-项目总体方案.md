# 工业销售管理系统 V2.0｜项目总体方案与产品需求基线

> 版本：V2.0（设计评审稿）｜日期：2026-11-12｜状态：方案建议，**尚未获得甲方正式开发确认**
>
> 依据：甲方《功能需求》《销售软件需求》、三份实际报价表、《问题确认表(1)》中的 14 条答复及补充说明；另参照 ERPNext、Odoo、Dolibarr、EspoCRM 官方公开资料。本文使用「已确认」「设计建议」「待确认」区分证据等级。

## 0. 执行摘要

**项目定位**：面向 1～5 人并发的小型工业销售团队，以项目为轴、报价为商务环节、进度为协作主线、已确认订单/合同为业绩依据、公开案例为对外展示出口的模块化 Web 管理系统。不是全功能 ERP，不做库存、采购、总账和复杂生产管理。

**首期闭环**：客户/联系人 → 项目（可独立存在、可关联多家客户）→ 销售跟进 → 商务报价（三公司固定模板）→ 线下发送/状态登记 → 合同/订单与负责人确认 → 项目执行进度 → 内部业绩台账 → 敏感信息剔除后的案例 PDF。

**五个确定性原则**：
1. 项目不是客户的子记录；一个项目可关联多个参与方，不得因为第一家主机厂录入就锁死归属。
2. 报价由商务助理与负责人创建，销售侧主要服务项目、跟进和业绩；权限不能沿用旧版“销售做报价”的假设。
3. 甲方选择三公司共享数据、仅模板区分；但报价必须携带明确的出具主体，不能仅凭品牌隐式确定公司。
4. **已发送报价的价格、参数、条款、模板、PDF 需要冻结快照**；产品库后续更新不可篡改历史。
5. **报价标记中标≠可确认业绩**；以合同/订单核验或负责人确认作为受控业务动作，禁止重复归集。

## 2. 产品边界和范围

### 2.1 P0 首期必须上线

- 账号密码登录、五类角色与服务器端授权、账号停用、密码重置；1～5 人并发。
- 经营首页：我的待办、最近项目、售前机会、执行中项目、业绩概览；随角色变化。
- 三家出具公司基础配置：名称、地址、联系方式、固定模板、固定条款、Logo（如有）；数据共享。
- 产品型号库：名称/型号/类别/品牌/图号/单位/税率/参数字典/参数值/技术说明/图片；商务和负责人可新增、编辑、停用；基本 Excel 导入。
- 客户组织：一个组织多身份（主机厂、投资方、代理商、贸易商、业主、总包等），多个联系人、部门、职务；按条件筛选和查重。
- 项目台账：独立建项、多个参与方与角色、区域、行业、主机类型、投资方、负责人、跟进阶段、备注/附件；项目详情 360° 关联客户、报价、合同/订单、进度和业绩。
- 售前跟进：记录时间、阶段、联系对象、跟进内容、下次行动、附件；销售与商务助理可写。
- 商务报价：三公司固定模板、产品行选择、参数可选显示、单价/数量/税率编辑、自动汇总、客户联系人、报价条款、编号与版本、PDF 预览与下载、按项目/客户/型号搜索历史。
- 报价生命周期：草稿、已生成、已发送、已取消、已失标、已接受（状态仅为商务事实，不直接等于业绩）；已生成 PDF 的历史版本保持不变。
- 合同/订单确认记录：可关联项目及报价、确认时间、确认依据（合同/订单或负责人授权）、数量/金额（按权限）、证据附件；防重复归集业绩。
- 项目执行进度：节点、最新状态、责任人、预计/实际日期、文字日志、附件；商务助理和财务写执行阶段，销售看允许公开给内部销售的进度摘要。
- 业绩台账：中标确认后生成或手动补录，标记产品/主机/投资方/年份/地区/证明文件；销售查授权范围；负责人看全部及内部统计。
- 外部案例：人工挑选项目业绩、脱敏字段白名单、图片与简介、固定版式 PDF；不提供合同金额/报价/成本/利润。
- 数据导出、操作日志、自动备份及恢复演练、附件白名单和访问授权。

### 2.2 P1 体验完善，视首期余量再做

- 项目阶段看板、可配置常用视图、移动端轻操作、项目提醒与逾期待办、丰富图表、多条件批量导出。
- 进度通知邮件/企业微信、模板条款后台编辑更多项、案例 PDF 主题、多角色汇报看板。

### 2.3 明确不属于 P0

- 真正离线本地应用与数据双向自动同步；手机原生 APP；外部客户登录门户；地图标注和 GIS；泛化 Word/Excel 版式设计器；复杂多级审批及法律电子签章；ERP 采购/库存/总账/开票；自动铜价和汇率第三方接口；项目执行的完整工业生产排程。

## 4. 核心业务流程与状态模型

### 4.1 售前流程

`客户/参与方资料 → 创建独立项目 → 关联多个主机厂/业主/投资方 → 销售或商务维护项目跟进 → 商务选定“报价接受方” → 商务确定出具公司 → 加入产品型号及参数 → 修改数量与价格 → PDF 预览和生成（冻结快照） → 线下发送 → 手工登记已发送/已失标/已接受`

**不变量**：项目可以没有客户；报价必须明确接收客户；一项目可有多份报价，并可能对应不同接收客户或出具公司；报价价格只属于本版本。

### 4.2 订单与业绩流程

`已接受报价/线下直接签约 → 上传合同/订单证明或负责人手动确认 → 系统检查重复 → 新建确认记录 → 关联至少一条业绩 → 项目进入合同执行阶段 → 后续执行里程碑 → 业绩对外案例候选 → 人工核对公开字段 → 生成客户案例 PDF`

**不变量**：不能仅凭报价状态=“已接受”自动记为签约业绩。支持无报价的线下业绩录入，但必须提供原因和确认责任人；同一订单号/合同号在同一主体下应阻断重复，允许由负责人明确处理例外。

### 4.3 执行进度流程

建议首期配置式节点：`订单已确认 → 技术资料确认 → 生产/备货 → 发货 → 到货 → 安装/调试 → 验收 → 完成`。并非每类产品都必须走完全部节点；节点可以标“跳过/不适用”。

执行事件字段：阶段、原状态、新状态、进展说明、负责人、预计完成日、实际完成日、附件、更新时间与操作人。财务附加字段（回款、发票、合同金额）放在**独立财务授权视图**，不给销售的项目进度 API 返回。

### 4.4 项目和报价生命周期必须分开

- 项目售前阶段：线索发现 / 初步沟通 / 技术交流 / 报价中 / 投标中 / 结果待定 / 失标 / 成交。
- 项目执行阶段：未启动 / 执行中 / 暂停 / 已验收 / 已关闭。
- 报价状态：草稿 / 已生成 / 已发送 / 已接受 / 已失标 / 已取消。
- 业绩状态：待核实 / 已确认 / 已撤销（撤销要保留审计记录）。

一个项目的某份报价“失标”，并不代表项目整体失标；其他主机厂仍可能中标。同一项目也可能存在多次合同或追加订单。

## 5. 报价引擎：可实现且可长期维护的设计

**先用固定的三套 HTML/CSS 打印模板生成 PDF**，模板通过公司 ID 选择。产品字段、参数选择、税率、行小计、未税/含税总计、商务条款均由后台数据驱动，价格允许商务助理手工改。第一期仅支持人民币和常规含税计算，电缆铜价联动等复杂规则先作为手动调整备注，若经样本验证再加入**有限规则类型**，禁止客户自写公式执行代码。

报价行字段：`product_id, model_snapshot, description_snapshot, parameter_snapshot[], visible_parameter_keys[], unit, qty_decimal, unit_price_decimal, tax_rate_decimal, discount_decimal, currency, line_net, line_tax, line_gross`。

**计算规定（建议待确认）**：单价默认未税；单行未税额 = 数量 × 单价 × (1−折扣率)；税额 = 对单行未税额 × 税率做约定舍入；含税额 = 未税额 + 税额；单据汇总按行金额求和。币种、折扣与计税口径以样本正式确认，不可在开发时猜测。后端使用 Decimal，不用二进制浮点金额；前后端相同计算样例对账。

版本策略：`QUOTE-2026-0001-V1`。生成 PDF 时存原始 snapshot、模板版本、文件 SHA-256、生成者和时间。任何已发出版本都不可原地更新；复制生成 V2。旧产品停用不影响历史报价的打开与下载。

**模板首期边界**：三套固定页面设计，支持 logo、抬头字段、页脚条款、默认印刷说明和价格编辑；不承诺“上传任何现有 Word/Excel 自动识别公式及排版”。旧 `.xls` 与 `.xlsx` 可作为数据迁移和视觉参考，但不要在运行时直接执行其宏或公式。

| account | name, normalized_name, industry, region, status | 公司组织统一库，去重提示 |

| order_confirmation | project_id, order_ref, basis, confirmed_by, proof | 去重、权限和撤销留痕 |

## 7. 交互与前端信息架构

### 7.1 侧栏（按角色显示）

- **工作台**：我的待办、项目动态、需要关注、下一步操作；销售视角隐藏商业金额。
- **项目中心**：筛选/项目详情/参与方/售前进展/执行里程碑/关联资料。
- **客户中心**：组织列表/联系人树/关联项目/行业标签。
- **产品型号**：商务与负责人；分类/参数维护/Excel 导入。
- **报价中心**：商务与负责人；列表/新建/历史版本/预览/生成。
- **项目执行**：商务与财务；按节点看项目列表和逾期项。
- **业绩与案例**：内部业绩/对外案例筛选/案例 PDF。
- **系统设置**：用户/角色/报价主体/模板参数/数据字典/备份状态。

### 7.2 关键页面

1. 项目详情为最重要的工作页面：顶部项目信息+状态，左侧参与方及产品，中央双阶段时间轴，右侧待办、报价和订单。所有角色看同一项目但有不同可见/可编辑字段。
2. 报价新建分四步：选报价主体与接收客户 → 产品型号与技术参数 → 价格及商务条款 → PDF 预览与生成。避免 40 字段一次铺满。
3. 销售主页强调“我的项目、最近跟进、即将到期、执行节点、我的业绩”，而非报价金额 KPI。
4. 财务主页强调“执行中项目、待更新节点、合同/订单证明、资金信息专用区”，不承担报价编辑。
5. 案例构建页为两栏：左侧经过筛选的候选业绩，右侧已选案例及公开字段预览；生成时白名单取数。

设计语言：深海蓝导航、白底卡片、薄荷绿操作强调，1280～1440 宽屏优先；表格行高 42～48px；每个列表有搜索、筛选、空态和错误提示；移动端支持进度查看与轻量跟进，不承诺复杂报价编辑。

## 8. 技术架构与部署

**推荐**：React + TypeScript + Ant Design（前端）；Django 5.2 LTS + Django REST Framework（后端）；PostgreSQL（事务数据）；Nginx（HTTPS/同源代理）；本地私有目录存储附件并独立备份（或对象存储）；HTML/CSS 打印模板 + Chromium/PDF 引擎（容器隔离、网络禁用、资源限额）。也可以根据开发团队熟悉度改为 Vue 3，原则是减少技术栈数量，不做微服务。

**部署**：建议一台 Linux 云服务器，初期估算 2 vCPU / 4GB RAM / 80GB SSD 可作为预研起点；上传大图及 PDF 生成并发可能增加内存占用，容量须在 UAT 压测校正。使用 Docker Compose 部署 `nginx + web + api + postgres`，数据库和文件存储不对公网开放。使用现有域名的独立子域名，HTTPS 强制启用，正式部署前核实 DNS/证书/中国内地备案要求等条件。

**系统入口**：浏览器登录；可把系统安装成桌面快捷方式或 PWA 样式入口；没有网络就不能进行写操作，**首期不承诺离线业务数据双向同步**。

**安全**：RBAC + 行级授权 + 字段级序列化 + 附件鉴权；密码安全散列，CSRF/Session 安全，限速，运维账户与业务账户分离，敏感导出审计，案例发布白名单；生产开启定时全量备份并进行月度恢复抽检。

## 13. 项目负责人审核结论

**建议进入 G0 技术验证与业务确认，不直接跳至全面编码。** G0 的关键不是做更多静态页面，而是证明三个难点可用：① 三公司实际报价单的生成与分页；② 项目—多客户—多报价—订单—业绩的数据关系；③ 销售与财务跨角色权限隔离及对外案例脱敏。

若 G0 三项通过，则按 G1–G4 分段交付，每一段包含真实数据库、API 契约、端到端测试和可回滚部署，避免大量页面做好却无法实际操作。
