3. G0 会议必须补足六个问题：本地软件是否只是桌面入口、销售是否可看无价格报价摘要、业绩确认规则“或/且”、模板与价税规则、财务执行信息范围、域名/云区域。

## 2. 技术基线建议

- **Backend**：Django 5.2 LTS + Django REST Framework + PostgreSQL；交易、权限、快照、审计优先。Python 3.12/3.13 可选，按部署目标稳定版本锁定。
- **Frontend**：React + TypeScript + Vite + Ant Design（按角色导航和单一页面设计系统），ECharts 仅在有真实统计数据后启用。
- **Deployment**：Docker Compose；Nginx HTTPS / SPA static / API same-origin / PostgreSQL private network；文件保存在受控数据卷，数据库备份与附件备份独立保存。
- **PDF**：固定公司模板 HTML/CSS，受控 Playwright/Chromium 打印 PDF 或服务端模板引擎；禁加载外部任意 HTML 或 JS；冻结模板版本、快照哈希与 PDF 哈希；字体嵌入与中文分页回归。
- **Excel**：初期仅批量导入产品、客户、业绩标准模板，先预检再执行；禁止执行用户上传 Excel 宏。
- **API**：推荐 Session + CSRF / SameSite Cookie + HTTPS，首期不需要 OAuth 微服务集群和消息队列。若确需 JWT，必须重新给出安全方案。
- **文件**：MIME/扩展名/签名校验、文件大小上限、私有下载 API、上传审计和备份；禁止公开对象直链。

## 4. G0：先做三个高风险 POC

### POC-A：三固定报价 PDF

- 以现有三份 Excel 为业务和打印参考，优先拿到甲方**最终三份样张**；取每套多产品行、长技术参数、分页和不同税率的测试用例。
- 单独建模板渲染服务，输出 3 个 PDF，并截图逐页对比；验证中文字体、长表分页、项目/接收客户/出具公司、金额大写（若需要）、商务条款和页脚。
- 快照变更测试：生成 V1 后调整产品价格与技术参数，重生成历史 V1 必须与原 PDF hash 相同；创建 V2 才发生变化。
- 公式 POC：明确单价含税/未税、折扣、税率、逐行舍入、金额币种；对照财务给出的 10 组黄金样例。不允许隐含 Excel `TODAY()` 或浮点误差影响历史报价。
- 交付：`docs/evidence/G0/pdf/` 下的 PDF、图、自动化断言、对照问题列表。

### POC-B：项目多参与方与多报价结构

- 建 PostgreSQL 最小迁移：`project`, `account`, `project_party`, `quote`, `quote_revision`, `quote_line_snapshot`, `order_confirmation`, `performance`。
- 通过事务验证：项目不绑定客户可建；关联三家参与方；项目创建两份不同出具主体、不同接受客户的报价；其中一份确认订单并生成业绩；另一份失标不影响项目；重复确认只生成一条业绩。
- 交付：实体关系图、迁移文件、测试 DB 回放脚本。

### POC-C：跨角色权限与公开材料

- 以角色 `ADMIN / LEADER / ASSISTANT / SALES / FINANCE` 创建测试矩阵；**服务端**验证行级和字段级权限。
- 禁止 Sales `GET /api/quotes/{id}/` 获取报价明细，或者在甲方确认的非金额摘要契约下仅返回明确允许字段；不能把 amount 留在 JSON 里靠 JS 隐藏。
- 财务对执行进度可写，对报价不能编辑；销售仅售前进度可写。
- 对外案例使用 schema allowlist 序列化器，只允许标题、年份、地区、项目类型、主机、产品、公开简介和明确授权图片；PDF 字节级敏感词、原始金额与 metadata 扫描。
- 交付：不小于 20 条权限自动化用例和失败截图/日志。

**G0 放行门槛**：上述三项有明确可复现 PASS，且六个待确认事项有决策记录；否则保持 G0，不推进“全量页面填充”。

## 5. G1：基础业务主线

- 建立登录、账号、角色分配、权限策略类；所有 API 经统一授权，后端响应不泄漏敏感字段。
- 三个法律出具主体配置及模板键。
- 客户：名称标准化、重复提示、多业务角色、多联系人、部门职务；客户详情查看关联项目。
- 产品：唯一 SKU/型号、类别、参数字典、税率、参考价、停用机制；商务和负责人新增、修改、停用；操作事件写 Audit。
- 项目：独立创建、多客户参与方（角色可重复但同项目同组织同参与方关系去重）、项目主机类型/区域/投资方、售前阶段、日志、附件。
- 前端：工作台/客户/项目/产品 4 模块；每个提交有实际 API、状态反馈、错误提示、审计。
- G1 验收：销售建立项目，无客户可保存；再关联两个主机厂和一个投资方；商务查看并补充记录；财务不能编辑售前日志；删除客户不可破坏引用的项目。

## 6. G2：报价交易与生成

- 分步表单：出具公司→项目→接收客户→产品→展示参数→数量/单价/税率/折扣/条款→预览与生成。
- 所有报价单的金额计算只信任后端 Decimal；API 返回行级未税金额、税额、含税金额、合计。
- 已生成版本不可修改旧明细，V2 用复制+新版本；PDF 生成成功后再将状态标记为 GENERATED；失败保留可重试状态且不发布半文件。
- 历史搜索按项目/接收客户/产品型号/时间/出具公司，多版本可见；只对授权角色开放。
- 禁止前端自定义模板 HTML/执行脚本；所有 PDF 使用签名存储，不允许通过目录猜路径下载。
- G2 验收：三套公司模板 10 种行组合/PDF 预览；金额黄金样例一致；同一个项目给两个接收单位不同报价；V1 hash 冻结。

## 7. G3：订单确认、执行与案例

- `OrderConfirmation` 状态机 `DRAFT -> CONFIRMED -> REVOKED`；确认接口幂等键；允许合同/订单及负责人确认两种来源，但未明确甲方选择“或/且”之前不得最终发布业务规则。
- 对应业绩由受控服务创建；手工历史业绩走单独来源及“待核实”状态，避免绕过订单验证；收益金额与业绩凭证分权限。
- 项目执行 Milestone + Update，预置有限节点，允许不适用、延期及说明；销售看脱敏摘要，商务/财务编辑执行。
- 公开 CaseRelease 与内部 Performance 隔离存储；公开序列化器白名单，不含内部 amount/quote_ref/cost/profit；生成案例册时留作者、发布时间、引用版本、PDF hash。
- G3 验收：对一个已确认订单生成唯一业绩；两人重复点击不重复；撤销保持痕迹；财务执行更新销售能看安全摘要；公开 PDF 全链路无泄漏。

## 8. G4：上线硬化、迁移与运维

- 明确产品/客户/历史业绩 Excel 表头、空值、必填和重复规则，预检查并返回带行号错误明细。重复导入同一文件不复制数据。
- 上传文件安全、下载授权、过大附件提示、用户停用与 Session 失效测试。
- 数据库全量备份 + 附件备份 + 加密 + 异机/对象存储保留，恢复演练出具 `restore-check` 日志；若只备份 DB 不备份 PDF/附件即失败。
- 云主机安全组仅 443/必要管理入口对外；PG、应用管理端不公开；HTTPS、CSP 及 CSRF 等安全基线。
- CI：后端测试+前端 lint/typecheck/build+数据库迁移自检+权限、金额、案例规则的重点测试。
- 甲方 UAT：五身份使用的 10 个黄金场景全部 PASS；出具培训手册、管理员手册、回滚方案和服务验收表。

## 9. API 契约草案（需在 G0 固定）

| Method | Endpoint | 角色/要点 |
|---|---|---|
| GET/POST | `/api/accounts/` | 内部用户按作用域读取，授权角色写入 |
| GET/POST | `/api/projects/` | 销售/商务可创建；可以无客户 |
| POST | `/api/projects/{id}/parties/` | 关联多组织及业务角色 |
| POST | `/api/projects/{id}/updates/` | 售前 SALES+ASSISTANT；执行 ASSISTANT+FINANCE |
| GET/POST | `/api/products/` | 读取视图按需；写入 ADMIN+LEADER+ASSISTANT |
| POST | `/api/quotations/` | ASSISTANT+LEADER+ADMIN |
| POST | `/api/quotations/{id}/revisions/` | 按新版本复制，旧版不可改 |
| POST | `/api/quote-revisions/{id}/render/` | 后端 Decimal & snapshot & PDF |
| GET | `/api/quote-revisions/{id}/pdf/` | 后端校验访问，生产 PDF 私有 |
| POST | `/api/order-confirmations/` | 受控确认与幂等 |
| GET/POST | `/api/performances/` | 按内部金额与公开字段分序列化器 |
| POST | `/api/case-releases/` | 仅白名单字段；必须核对图片授权 |
| GET | `/api/case-releases/{id}/pdf/` | 输出已冻结公开 PDF |
| POST | `/api/import-batches/preview/` | 预检查、重复识别，不写入 |
| POST | `/api/import-batches/{id}/commit/` | 防重复事务，授权后提交 |

**建议响应错误规范**：`{code, message, field_errors, request_id}`；每个写操作有 request_id、actor、审计资源 ID。要避免默认 ORM Serializer 在 `Project` 嵌套时把敏感报价/合同字段一起返回。

## 10. 最重要的自动化测试清单

- 权限：五角色 × 读/写/导出 × 敏感/非敏感资源；表格搜索和批量导出也要校验；不只 UI 层隐藏。
- 数据：项目无客户、项目多客户、多重身份、多轮报价、不同公司模板、报价失败重试、订单确认重复提交。
- 金额：数量、千分位、税率、折扣、部分参数、两位小数、重复生成、分项舍入；用 Decimal golden fixture。
- PDF：中文、长型号、长技术参数、长公司名称、分页/页脚、3 模板、报价失效后原 PDF 不变。
- 案例：公开字段不包含敏感数据；API、HTML、PDF、文件名、文档 metadata 均检查；未确认业绩不可发布。
- 恢复：备份恢复后 user roles、quote revision、PDF hash、项目/客户多对多关联一致。
- 性能：以 1～5 并发为基本基线；主要列表常规查询与 PDF 单份生成通过规定阈值；不要编造性能指标，G0 测量后写入 SLA。

## 11. 反向学习的合理边界

- 第一优先：**可公开访问的上游源代码、数据库迁移、官方 API 文档和开源演示**，例如 ERPNext 和 Dolibarr；可以直接研读其领域模型，不需要逆向。
- 第二优先：获得授权的成熟平台演示账号，使用浏览器对照工作流/信息架构；仅记录**行为和通用交互原则**，不复制商用素材、受保护代码和认证边界。
- 第三优先：确有黑盒行为、且拥有合法测试权限时，考虑 `morluto/rea` 的网页/JS 分析能力，用于机制研究，不作为产品运行依赖；必须记录目标、操作范围、证据和限制。
- 独立复刻系统需要自己的数据结构与设计，任何第三方源代码使用必须审核许可证和第三方依赖清单。

## 13. 项目负责人验收纪律

1. `0 warnings`、`console clean` 不等于业务可用；必须有真实 DB 和后端权限证明。
2. 实际实现和原型有差异，必须更新需求追踪矩阵，不得静默改变历史报价或对外案例安全策略。

4. 历史业务数据、报表导出、报价 PDF、附件权限是数据安全测试重点。
5. Git 保留最小机密原则：密钥、域名管理口令、真实项目资料不要写仓库。
6. 每个阶段有回滚和备份恢复办法；未通过 G4 不建议上线。
