# 工业销售管理系统 V2.1 — 局域网安装使用手册

适用版本：2.1.0-rc1（**交付候选 / 试用版**，正式版需完成现场验收后发布）。
本手册面向甲方负责安装的人员。按顺序操作即可在一台 Windows 主机上从零完成安装，并让局域网其他电脑通过浏览器使用。

## 1. 部署方式一览

- **一台 Windows 主机**长期开机，安装本系统（数据库 + Web 应用）。
- **其他电脑**只需浏览器（Edge / Chrome），打开主机地址即可，不安装任何软件。
- 所有人读写同一个数据库，数据实时共享；**断开互联网不影响局域网内使用**。
- 不需要云服务器、公网域名；数据库只在本机（127.0.0.1）监听，局域网无法直连数据库。

## 2. 主机要求与前置条件

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 1809 / Windows 11 / Windows Server 2019 及以上，**64 位** |
| 配置 | 建议 4 核、8 GB 内存、SSD；系统所在磁盘外最好另有一块盘用于备份 |
| 磁盘 | 安装盘至少 5 GB 可用，建议预留 50 GB（按附件规模调整） |
| 权限 | 安装时需要**本机管理员**（只用于注册服务、配置防火墙和目录权限；系统运行时使用低权限服务账户） |
| 网络 | 主机建议在路由器中做 **DHCP 保留**（固定 IP），或使用内网 DNS 名称 |
| 前置软件 | **无**。安装包已包含 Python 运行时、PostgreSQL 16、Visual C++ 运行库（微软签名，安装时自动安装） |

安装目录要求：放在本地磁盘的**纯英文路径**（例如 `D:\IndustrialSalesHub`，可以含空格）。PostgreSQL 按系统代码页处理路径，中文路径可能导致数据库无法启动，安装程序会拒绝。**不要放在 OneDrive/百度网盘/坚果云等同步盘、桌面或网络共享路径**。

## 3. 安装步骤

1. 核对安装包：`Industrial_Sales_Hub_<版本>_LAN_Windows_x64.zip` 与同名 `.sha256` 文件中的哈希一致（PowerShell：`Get-FileHash <zip> -Algorithm SHA256`）。
2. 右键 ZIP → 属性 → 勾选“解除锁定”（如有）→ 确定；然后解压到 `D:\IndustrialSalesHub`。
3. 打开解压目录，**右键 `01-安装部署.bat` → 以管理员身份运行**。安装程序会：
   - 检查系统版本、64 位、磁盘、内存、端口、是否同步盘；校验安装包所有文件的 SHA256；
   - 安装 VC++ 运行库；生成随机签名密钥与数据库密码（`config\app.env`）；
   - 初始化 PostgreSQL（只监听 127.0.0.1，独立应用账号 `ish_app`，非超级用户）；
   - 注册两个 Windows 服务（开机自启、故障自动重启、以虚拟服务账户运行）；
   - 设置目录权限（`config`、`data`、`backups` 仅管理员与服务账户可访问）；
   - 数据库迁移，导入三家出具主体的**占位配置**（不导入任何客户、项目或演示账号）；
   - **提示输入管理员用户名与密码**（密码输入两次，不显示、不写日志）；
   - 防火墙只放行应用端口（默认 8000），仅“专用/域”网络，远程范围默认本地子网；
   - 探活并打开浏览器，打印本机真实的局域网地址，生成 `客户端快捷方式\工业销售管理系统.url`。
4. 可选参数（在管理员命令行中）：
   `01-安装部署.bat -AppPort 8010 -DbPort 55433 -AllowedRemote 192.168.1.0/24`
5. 安装失败时：窗口会显示原因与退出码，详细日志在 `logs\install-*.log`。修正后**直接重新运行**即可（不会重复创建服务、不会重新生成密钥、不会覆盖已有数据）。

## 4. 首次使用

1. 用管理员登录 → **系统设置 → 账号与角色**：为负责人、商务助理、销售、财务分别建账号（密码至少 8 位且含字母和数字）。
   管理员是技术角色，**看不到报价、金额和业绩**，这是设计要求。
2. 用**部门负责人**登录 → 系统设置 → 报价出具主体：填写三家公司的合法全称、地址、电话、税号、开户行、条款、单价口径（含税/未税）。
   在真实样张核对并经财务签收前，不要勾选“模板已签收”。
3. 把 `客户端快捷方式` 文件夹中的 `.url` 复制到各同事电脑桌面，或告知 `访问地址.txt` 中的地址。
4. 运行 `04-立即备份.bat` 做第一次备份；以管理员身份运行 `08-配置每日备份.bat`（默认每天 02:00，错过时开机补做）。
5. 编辑 `config\app.env` 中 `ISH_BACKUP_COPY_TO=` 为另一块硬盘或另一台电脑的共享目录（例如 `E:\ISH备份` 或 `\\NAS\ish`），实现异盘/异机副本。

## 5. 日常操作

| 脚本 | 作用 | 需要管理员 |
|---|---|---|
| `02-启动系统.bat` | 检查并启动服务、打开浏览器、显示局域网地址。重复运行安全 | 仅当服务未运行时 |
| `03-停止系统.bat` | 停止应用（`-IncludeDatabase` 同时停数据库） | 是 |
| `04-立即备份.bat` | 一致性备份（期间约数秒只读） | 否（读写 backups 目录需权限） |
| `05-恢复备份.bat -BackupPath <目录>` | 默认**恢复演练**到临时库，不影响正式数据；加 `-Production` 才覆盖正式数据 | 覆盖时需要 |
| `06-检查系统.bat` | 只读检查：服务、端口、数据库监听、健康、备份时间、磁盘、防火墙、日志错误 | 否 |
| `07-升级程序.bat -NewPackageDir <新包目录>` | 升级（见备份恢复与升级手册） | 是 |
| `08-配置每日备份.bat` | 每日自动备份计划任务 | 是 |
| `99-卸载服务.bat` | 删除服务与防火墙规则，**默认保留数据** | 是 |

关闭命令窗口或浏览器**不会**停止系统；系统随 Windows 开机自动启动，不需要任何人登录。

## 6. HTTPS（建议）

安装默认是**“隔离内网 HTTP 试用”**：数据在局域网中未加密传输，登录页和系统状态会明确提示。正式使用建议：

1. 使用甲方已有的 IIS（URL Rewrite + ARR）或其他成熟反向代理，配置内部 CA 签发的证书（例如 `https://sales.公司内网:8443`）；
2. 代理转发到 `http://127.0.0.1:8000`；在 `config\app.env` 中设置：
   `ISH_HTTPS=1`、`ISH_TRUST_PROXY_HEADER=1`、`ISH_LISTEN=127.0.0.1:8000`、`ISH_TRUSTED_PROXY=127.0.0.1`，
   并把内网域名加入 `DJANGO_ALLOWED_HOSTS` 与 `DJANGO_CSRF_TRUSTED_ORIGINS`；
3. 防火墙改为放行代理端口；重启应用服务。
不要让用户点击“继续访问不安全网站”绕过证书告警；证书应由内部 CA 签发并下发到各客户端。

## 7. 角色与权限（简表，完整矩阵见 `docs/权限矩阵.md`）

| 角色 | 主要工作 | 看不到 |
|---|---|---|
| 管理员 | 账号、出具主体基础配置、系统状态 | 项目、报价、金额、业绩 |
| 部门负责人 | 全部业务、确认/撤销、业绩汇总、案例管理 | — |
| 商务助理 | 产品、报价（四步、版本冻结）、合同确认、执行节点、业绩补录 | — |
| 销售 | 登记项目、自己项目的跟进、全团队执行进度（只读）、我的业绩、可公开案例 | 报价中心、价格、合同/财务金额、他人业绩 |
| 财务 | 合同/订单确认状态、执行与交付节点 | 报价、所有金额（本期无回款/开票台账） |

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 其他电脑打不开 | 运行 `06-检查系统.bat`；确认主机 IP 未变、网络为“专用”、防火墙规则存在、对方与主机同一网段 |
| 打开显示 “Bad Request (400)” | 访问用的地址（IP/计算机名）不在 `DJANGO_ALLOWED_HOSTS` 中：编辑 `config\app.env` 加入后重启应用服务 |
| 提示“系统正在备份或维护” | 正在备份，稍候自动恢复；若长时间不恢复，查看 `logs\backup-*.log`，必要时删除 `data\MAINTENANCE` |
| 端口被占用 | 重新安装时加 `-AppPort 8010` |
| 忘记管理员密码 | 另一个管理员可重置；只有一个管理员时，在主机管理员命令行运行 `runtime\python\python.exe app\backend\manage.py changepassword <用户名>`（需先设置环境变量 `ISH_CONFIG_FILE=<安装目录>\config\app.env`） |

## 9. 迁移到 Linux / 云服务器（可选，后续）

1. 在 Windows 上运行 `04-立即备份.bat`，得到 `db.dump` + `private\`；
2. Linux 主机安装 PostgreSQL 16 与 Python 3.12，或使用仓库中的 `infra/compose.yml`（CLOUD 模式）；
3. `pg_restore --no-owner -d <库> db.dump`；把 `private\` 复制到新 `DATA_DIR/private`；
4. 设置 `ISH_MODE=LAN`（内网 Linux）或 `CLOUD`，运行 `python manage.py migrate` 与 `python manage.py verify_integrity`；
5. 以 Waitress（`python serve.py`）或 gunicorn（CLOUD）启动。本轮未实际执行云部署。
