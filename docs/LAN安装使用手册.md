# 工业销售管理系统 V2.1 — 局域网安装使用手册

适用版本：2.1.0-rc3（**两板块与现场验收候选**，不是正式版；正式 2.1.0 需负责人确认全部发布阻断关闭后封板）。
实机验收步骤与证据清单见 `RC2-Windows实机验收手册.md` + `RC3-Windows实机验收手册.md`；HTTPS 见 `RC2-HTTPS内网证书配置手册.md`；日常业务操作见 `RC3-用户操作手册.md`。
本手册面向甲方负责安装的人员。按顺序操作即可在一台 Windows 主机上从零完成安装，并让局域网其他电脑通过浏览器使用。

## 1. 部署方式一览

- **一台 Windows 主机**长期开机，安装本系统（数据库 + Web 应用）。
- **其他电脑**只需浏览器（Edge / Chrome），打开主机地址即可，不安装任何软件。
- 所有人读写同一个数据库，数据实时共享；**断开互联网不影响局域网内使用**。
- 不需要云服务器、公网域名；数据库只在本机（127.0.0.1）监听，局域网无法直连数据库。

## 2. 主机要求与前置条件

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 11 x64（RC2 实机验收目标）；Windows 10 1809+ / Server 2019+ 脚本支持但**未在目标机实测**，现场需单独验收 |
| 配置 | 建议 4 核、8 GB 内存、SSD；系统所在磁盘外最好另有一块盘用于备份 |
| 磁盘 | 安装盘至少 5 GB 可用，建议预留 50 GB（按附件规模调整） |
| 权限 | 安装时需要**本机管理员**（只用于注册服务、配置防火墙和目录权限；系统运行时使用低权限服务账户） |
| 网络 | 主机建议在路由器中做 **DHCP 保留**（固定 IP），或使用内网 DNS 名称 |
| 前置软件 | **无**。安装包已包含 Python 运行时、PostgreSQL 16、Visual C++ 运行库（微软签名，安装时自动安装） |

安装目录要求：放在本地 NTFS 磁盘的**纯英文路径**（例如 `C:\Program Files\ISH-Deploy` 下，可以含空格）。安装包应先复制和校验，再解压到普通用户无法修改文件或替换目录的位置。PostgreSQL 按系统代码页处理路径，安装程序会拒绝中文路径。
路径中不得含 `& < > " ' % ! ^ ; ` $`（会破坏服务配置与批处理参数，安装程序拒绝，退出码 14）。**不要放在 OneDrive/百度网盘/坚果云等同步盘、桌面或网络共享（UNC）路径**。
同一台主机只能有一套安装：若已存在同名服务但属于另一个目录，安装程序拒绝（退出码 18），请在原目录卸载或修复。

## 3. 安装步骤

1. 从交付方取得对应版本 ZIP 与已核验的 SHA256。
2. 在 **64 位管理员 Windows PowerShell** 中编辑前两行后执行下列命令。示例在 Program Files 下新建一个仅 Administrators 和 SYSTEM 可访问的目录，把 ZIP 复制到该目录后校验并解压。若目录已存在，请先确认用途。首次安装可选用新的英文目录名，修复或续装请使用原已校验目录并跳到第 3 步。

   ```powershell
   $zip = 'C:\path\to\Industrial_Sales_Hub_2.1.0-rc3_LAN_Windows_x64.zip'
   $expected = '<交付方提供的 64 位十六进制 SHA256>'
   $ErrorActionPreference = 'Stop'
   $stage = Join-Path $env:ProgramFiles 'ISH-Deploy'
   if (Test-Path -LiteralPath $stage) { throw "目录已存在：$stage" }
   $acl = [Security.AccessControl.DirectorySecurity]::new()
   $acl.SetAccessRuleProtection($true, $false)
   $acl.SetOwner([Security.Principal.SecurityIdentifier]::new('S-1-5-32-544'))
   foreach ($sid in 'S-1-5-18', 'S-1-5-32-544') {
       $id = [Security.Principal.SecurityIdentifier]::new($sid)
       $acl.AddAccessRule([Security.AccessControl.FileSystemAccessRule]::new(
           $id, 'FullControl', 'ContainerInherit,ObjectInherit', 'None', 'Allow'))
   }
   [IO.Directory]::CreateDirectory($stage, $acl) | Out-Null
   $verifiedZip = Join-Path $stage 'package.zip'
   Copy-Item -LiteralPath $zip -Destination $verifiedZip
   if ((Get-FileHash -LiteralPath $verifiedZip -Algorithm SHA256).Hash -ne $expected) {
       throw '安装包 SHA256 不匹配'
   }
   Expand-Archive -LiteralPath $verifiedZip -DestinationPath $stage
   ```

3. 在同一管理员窗口进入解压生成的 `Industrial_Sales_Hub_<版本>_LAN_Windows_x64` 子目录，运行 `& '.\01-安装部署.bat'`。安装程序会：
   - 检查系统版本、64 位、磁盘、内存、端口、是否同步盘；校验安装包所有文件的 SHA256；
   - 在生成配置和凭据之前保护配置、数据、日志和备份目录，检查普通用户无法替换提权执行所需的目录与文件。发现不安全的权限时停止，退出码为 27；
   - 安装 VC++ 运行库（**返回 3010 = 需要重启**：安装程序记录“等待重启”状态并以退出码 3010 结束；请重启 Windows 后**再次运行** `01-安装部署.bat`，
     会从中断处继续；未重启就重跑会再次提示重启，不会误报数据库损坏）；生成随机签名密钥与数据库密码（`config\app.env`）；
   - 使用一次性 SYSTEM 任务初始化 PostgreSQL，临时密码文件仅 Administrators 和 SYSTEM 可访问。完成后清理临时密码文件及任务。数据库只监听 127.0.0.1，应用账号 `ish_app` 为非超级用户；
   - 注册两个 Windows 服务（开机自启、故障自动重启、以虚拟服务账户运行）；
   - 设置目录权限（`config`、`data`、`backups` 仅管理员与服务账户可访问）；
   - 数据库迁移；**只创建缺失的**三家出具主体占位记录（create-only：重复安装不修改已有主体、条款、价税口径、Logo、签收）；不导入任何客户、项目或演示账号；
   - **提示输入管理员用户名与密码**（密码输入两次，不显示、不写日志）；
   - 防火墙只放行应用端口（默认 8000），规则名 `Industrial Sales Hub App (TCP 8000)`，仅“专用/域”网络，远程范围默认本地子网；
     安装/卸载**只删除本程序的应用端口规则**，管理员手工建立的 `Industrial Sales Hub HTTPS (443)` 等规则不受影响（RC3）；
   - 探活，打印本机局域网地址（优先有默认网关的实体网卡；有多块网卡/虚拟网卡时列出全部并提示用 `-PreferredIp` 指定），
     生成 `客户端快捷方式\工业销售管理系统.url`；HTTP 模式打开本机浏览器，**HTTPS 模式不打开 HTTP 登录页**（请用代理的 https 地址访问）；
   - 最后核对敏感目录权限（`config`、`data`、`logs`、`backups` 普通用户不可读；安装根目录、`scripts`、`runtime`、`app` 普通用户只读），不符合即失败（退出码 27）。
   安装全过程持有运维锁：备份/恢复/升级进行中时安装会提示“另一个运维任务正在进行”（退出码 75）。
4. 可选参数（在管理员命令行中）：
   `01-安装部署.bat -AppPort 8010 -DbPort 55433 -AllowedRemote 192.168.1.0/24 -PreferredIp 192.168.1.20`
   （`-PreferredIp`：多网卡主机指定写入快捷方式/访问地址的 IP；也可在 `config\app.env` 设置 `ISH_PREFERRED_IP`，`06-检查系统` 与 `02-启动系统` 同样采用）
5. 安装失败或中断时：窗口会显示原因与退出码，详细日志在 `logs\install-*.log`，进度记录在 `data\install-state.json`。修正后**直接重新运行**即可
   （沿用已生成的应用配置，不会重复创建服务或覆盖已有正式数据）。数据库初始化从独立的 `data\pgdata-init-*` 暂存目录开始，完成后才发布到 `data\pgdata`。如初始化中断，暂存目录留作排查，续装使用新的暂存目录。如果正式数据库目录存在却缺少必要文件或配套凭据，请保留现场并联系实施人员。

## 4. 首次使用

1. 用管理员登录 → **系统设置 → 账号与角色**：为负责人、商务助理、销售、财务分别建账号（密码至少 8 位且含字母和数字）。
   管理员是技术角色，**看不到报价、金额和业绩**，这是设计要求。
2. 用**部门负责人**登录 → 系统设置 → 报价出具主体：选择版式（A/B/C），填写中英文全称、地址、电话、税号、开户行、条款、单价口径（含税/未税），上传 Logo。
   也可由管理员在主机上用 `09-导入主体配置.bat -ConfigFile <真实配置.json> -AuthorizedBy <负责人用户名>` 导入（先预览差异、写审计；真实配置文件只保存在主机 `config\` 下）。
3. **模板签收（仅部门负责人）**：用真实样张逐项核对试用 PDF、财务核对 10 组黄金用例后，在主体卡片中填写签收依据并点击“负责人签收”。
   未签收时只能生成带“试用 · 模板未签收”水印的试用报价，不能标记为已发送、不能作为合同依据；签收只阻断正式报价，不影响其他模块使用。
   修改全称/英文名/版式/标题/价税口径/Logo 后签收自动失效，需要重新签收。
4. 把 `客户端快捷方式` 文件夹中的 `.url` 复制到各同事电脑桌面，或告知 `访问地址.txt` 中的地址。
5. 以管理员身份运行 `04-立即备份.bat` 做第一次备份；以管理员身份运行 `08-配置每日备份.bat`（默认每天 02:00，以 SYSTEM 运行，错过时开机补做；
   遇到恢复/升级等运维任务时最多等待 30 分钟，仍忙则安全跳过，退出码 75，不覆盖上次备份状态）。
6. 编辑 `config\app.env` 中 `ISH_BACKUP_COPY_TO=` 为另一块硬盘目录（例如 `E:\ISH备份`），实现异盘副本；副本先写入临时目录、校验通过后才改名，失败只告警。
   计划任务以 SYSTEM 运行，访问网络共享（`\\NAS\ish`）需要该共享对主机计算机账户授权，现场需单独验证。

## 5. 日常操作

| 脚本 | 作用 | 需要管理员 |
|---|---|---|
| `02-启动系统.bat` | 检查并启动服务、打开浏览器、显示局域网地址。重复运行安全 | 仅当服务未运行时 |
| `03-停止系统.bat` | 停止应用（`-IncludeDatabase` 同时停数据库） | 是 |
| `04-立即备份.bat` | 一致性备份（期间约数秒只读）；其他运维任务进行中时退出码 75 | 是（backups/data 仅管理员可访问） |
| `05-恢复备份.bat -BackupPath <目录>` | 默认**恢复演练**到临时库，不影响正式数据；加 `-Production` 正式恢复（staging 验证 + 原子切换 + 失败自动回退）；`-Rollback <ID>` 撤销；`-Cleanup <ID>` 清理旧数据 | 是 |
| `06-检查系统.bat` | 只读检查：服务、端口、数据库监听、健康、备份时间、磁盘、防火墙、维护状态与未完成的升级/恢复、日志错误 | 否（读 config 需管理员） |
| `新包目录\07-升级程序.bat -InstallDir <安装目录>` | 升级（**从新版本安装包目录运行**；见备份恢复与升级手册） | 是 |
| `09-导入主体配置.bat` | 导入真实出具主体配置（负责人授权、写审计、不改签收） | 是 |
| `08-配置每日备份.bat` | 每日自动备份计划任务 | 是 |
| `99-卸载服务.bat` | 删除服务与本程序的应用端口防火墙规则（保留手工 HTTPS 规则），**默认保留数据** | 是 |

关闭命令窗口或浏览器**不会**停止系统；系统随 Windows 开机自动启动，不需要任何人登录。

## 6. HTTPS（正式使用建议）

安装默认是**“隔离内网 HTTP 试用”**：数据在局域网中未加密传输，登录页和系统状态会明确提示。正式使用请按 `RC2-HTTPS内网证书配置手册.md`：
内部 CA 证书 + 反向代理（应用只监听 127.0.0.1，防火墙不开放应用端口）；新装可直接 `01-安装部署.bat -Https`。
不要让用户点击“继续访问不安全网站”；无证书的正式例外必须有甲方书面授权并单独记录。

## 7. 角色与权限（简表，完整矩阵见 `docs/权限矩阵.md` 与 `docs/RC3-业务角色与字段矩阵.md`）

首层分两个业务板块：**商务工作区**（负责人、商务助理、财务）与**销售工作区**（销售）；管理员只有技术设置。

| 角色 | 主要工作 | 看不到 |
|---|---|---|
| 管理员 | 账号、出具主体基础配置、系统状态 | 项目、报价、金额、业绩 |
| 部门负责人 | 全部业务、确认/撤销、业绩汇总、案例管理 | — |
| 商务助理 | 询价登记与登记单 PDF、产品、报价（版本冻结）、中标确认/转交、合同确认、生产交付状态、业绩补录 | — |
| 销售 | 登记项目、自己项目的跟进（中标转交后只读）、全团队交付/资金状态（只有状态，无金额）、经授权的交付文件、我的业绩与内部业绩 PDF（默认仅已确认）、可公开案例 | 报价中心、价格、合同/业绩金额、内部说明、他人业绩、内部附件 |
| 财务 | **报价中心（制作/修改/查看三公司报价、历史价格）**、询价登记、项目资料、合同/订单确认（不录合同金额）、生产交付与资金状态、业绩非金额字段 | 合同金额、业绩内部金额、合同证据附件；不能签收模板、审批业绩、修改公开授权（本期无回款/开票台账）。管理员可在 `config\app.env` 设 `ISH_FINANCE_QUOTE=0` 关闭财务报价 |

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| 其他电脑打不开 | 运行 `06-检查系统.bat`；确认主机 IP 未变、网络为“专用”、防火墙规则存在、对方与主机同一网段 |
| 打开显示 “Bad Request (400)” | 访问用的地址（IP/计算机名）不在 `DJANGO_ALLOWED_HOSTS` 中：编辑 `config\app.env` 加入后重启应用服务 |
| 提示“系统正在备份或维护” | 正在备份，稍候自动恢复；若长时间不恢复，运行 `06-检查系统.bat` 查看是哪个任务、是否有未完成的升级/恢复，按提示执行 `-Rollback`。**不要直接删除 `data\MAINTENANCE`**（升级/恢复失败时它保护半完成的数据不被写入） |
| 端口被占用 | 重新安装时加 `-AppPort 8010` |
| 忘记管理员密码 | 另一个管理员可重置；只有一个管理员时，在主机管理员命令行运行 `runtime\python\python.exe app\backend\manage.py changepassword <用户名>`（需先设置环境变量 `ISH_CONFIG_FILE=<安装目录>\config\app.env`） |

## 9. 迁移到 Linux / 云服务器（可选，后续）

1. 在 Windows 上运行 `04-立即备份.bat`，得到 `db.dump` + `private\`；
2. Linux 主机安装 PostgreSQL 16 与 Python 3.12，或使用仓库中的 `infra/compose.yml`（CLOUD 模式）；
3. `pg_restore --no-owner -d <库> db.dump`；把 `private\` 复制到新 `DATA_DIR/private`；
4. 设置 `ISH_MODE=LAN`（内网 Linux）或 `CLOUD`，运行 `python manage.py migrate` 与 `python manage.py verify_integrity`；
5. 以 Waitress（`python serve.py`）或 gunicorn（CLOUD）启动。本轮未实际执行云部署。
