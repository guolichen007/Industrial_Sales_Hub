# ADR-001 总体架构：轻量级模块化单体 + 云端集中数据

- 状态：已采纳（技术决策）；其中“不做离线同步”依赖甲方确认 D1
- 日期：2026-11-19

## 背景

1～5 人同时使用；甲方已确认租用云服务器、已有域名、常规数据库、三公司数据共享。核心是“项目为轴”的业务闭环，而不是库存、采购、总账。

## 决策

1. **自主开发模块化单体**：Django 5.2 LTS + Django REST Framework + PostgreSQL；前端 React + TypeScript + Vite。不引入 ERPNext/Odoo 整套二次开发（大量模块用不上，维护成本高），只借鉴其数据关系与不变量。
2. **按业务域拆分 Django app**：accounts / organizations / products / projects / quotations / contracts / performances / files / imports / audit。
3. **同源部署**：Nginx(HTTPS) → gunicorn(Django，同时托管前端构建产物) → PostgreSQL（仅内网）。会话 Cookie + CSRF，不用 JWT。
4. **“本地软件”的实现方式**：浏览器访问 + PWA 清单（可安装为桌面快捷方式）。所有电脑读写同一数据库，天然实时共享。**不实现离线编辑与双向同步**。
5. **前端使用手写 CSS（沿用已评审原型的视觉规范）而非 Ant Design**：减少依赖体积和构建时间，保持与甲方已看过的原型一致。若后续页面增多可再引入组件库。

## 后果

- 断网时无法写入数据（可接受，首期无离线需求）。
- 若甲方坚持“完全离线的本地软件”，需新增本地数据库、同步队列、冲突解决，工作量显著增加，必须重新评估工期。
