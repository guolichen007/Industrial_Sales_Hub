# ADR-002 报价冻结、金额计算与 PDF 生成

- 状态：已采纳（技术决策）；价税口径依赖甲方确认 D4
- 日期：2026-11-19

## 决策

1. **报价 = 业务容器（Quote）+ 版本（QuoteRevision）+ 行（QuoteLine）**。Quote 绑定项目、接收客户、出具主体；价格、参数、条款全部在版本里。
2. **加入报价行时从产品库复制**型号、名称、参数、单价、税率；之后与产品库解耦。产品停用/改价不影响任何报价。
3. **生成 = 冻结**：生成 PDF 时写入完整快照 JSON、快照 SHA-256、模板键与模板版本、PDF SHA-256、生成人与时间。版本状态变为 GENERATED 后，所有修改接口返回 409。修改只能“复制为新版本”。
4. **PDF 只成功才冻结**：渲染失败时记录 `last_error`、保持草稿，可修正后重试；不会留下半个文件（写入 `.part` 后原子改名）。
5. **金额只信任后端 Decimal**：前端传来的合计字段一律忽略。默认口径见 `apps/common/money.py`（未税单价、逐行 HALF_UP 舍入、合计为行之和）。
6. **PDF 引擎选择 ReportLab（纯 Python）而非 Chromium 打印**：
   - 不需要在服务器上运行浏览器，镜像小、内存占用低（2C4G 服务器足够）；
   - 不渲染任何用户 HTML/JS，从根本上排除模板注入；
   - 设置 `invariant=1`，同一快照多次渲染**字节完全一致**，可用哈希证明历史报价未被篡改（自动化测试已验证）。
   - 代价：版式由代码定义，修改样式需要开发人员；甲方首期确认为“三套固定模板”，可以接受。
7. **中文字体嵌入**：优先使用 `PDF_FONT_PATH`，其次自动查找微软雅黑/黑体/Noto/文泉驿等；若中文字体不含拉丁字符，会自动用 DejaVu/Arial 混排数字和英文。部署镜像内置 Noto Sans CJK。
8. **私有存储**：PDF 与附件保存在 `DATA_DIR/private`，文件名为随机 UUID；只能通过鉴权接口下载，下载时校验哈希。
