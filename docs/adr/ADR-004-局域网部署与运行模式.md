# ADR-004 局域网部署与运行模式（V2.1）

- 状态：已采纳（覆盖 ADR-001 中“云端集中部署”为首期目标的部分；ADR-003 的权限原则继续有效）
- 日期：2026-11-19

## 决策

1. **三种运行模式** `ISH_MODE`：
   - `DEMO`：本机演示，可 SQLite、可 DEBUG、可写演示数据；`ALLOWED_HOSTS` 强制为回环地址，局域网无法访问；Waitress 入口也强制 127.0.0.1。
   - `LAN`（首期唯一生产基线）：禁止 DEBUG、开发密钥（且密钥 ≥ 50 字符）、SQLite、`ALLOWED_HOSTS=*`、`seed_demo`；必须 PostgreSQL；写滚动日志。
   - `CLOUD`：保留原 Docker Compose + Nginx + gunicorn，本期不验收。
2. **WSGI**：Waitress 3.0.2（Windows 原生），默认 6 线程；`clear_untrusted_proxy_headers=True`，只有配置 `ISH_TRUSTED_PROXY` 时才信任代理头。gunicorn 不作为 Windows 入口。
3. **HTTPS**：Waitress 不终止 TLS。`ISH_HTTPS=1` 表示前面有可信 HTTPS 反向代理（IIS/内部 CA 等），此时 Secure Cookie + HSTS（局域网仅 1 天、不含子域名、不 preload）+ COOP。
   `ISH_HTTPS=0` 为“隔离内网 HTTP 试用”：不设 Secure Cookie/HSTS（否则 HTTP 下无法登录），登录页与系统状态明示“传输未加密”，**不作为正式安全基线**（LAN-05 正式门禁另审）。
   `X-Forwarded-Proto` 只在 `ISH_TRUST_PROXY_HEADER=1` 时信任，防止直连时伪造（已用 curl 验证伪造头不会使 Cookie 变为 Secure）。
4. **数据库**：PostgreSQL 16.16（EnterpriseDB Windows x64 二进制，Authenticode 签名已核验），`listen_addresses=127.0.0.1`、`pg_hba` 仅回环 scram-sha-256；应用使用独立非超级用户 `ish_app`；超级用户密码仅写入受保护的 `config` 目录。SQLite 只用于 DEMO：行锁与金额事务只在 PostgreSQL 上经过验证。
5. **Windows 服务**：WinSW 2.12.0 包装两个服务（DB、App），自动启动、App 延迟启动并依赖 DB、失败后 10/30/60 秒重启；以**虚拟服务账户** `NT SERVICE\<服务名>` 运行（低权限，无需密码）。
   目录 ACL：`config`、`data\pgdata`、`data\private`、`backups` 仅 SYSTEM、Administrators 与对应服务账户。
6. **写一致性**：所有 `/api/` 写请求在单一事务中执行并持有 advisory 共享锁；响应 ≥ 400 时整体回滚。备份时维护标志 + 排他锁保证数据库与私有文件处于同一时刻（见《备份恢复与升级手册》）。
7. **防火墙**：只放行应用端口，Profile=Private,Domain，RemoteAddress 默认 LocalSubnet；数据库端口不放行；不做任何公网端口映射。
8. **安装包**：由固定提交 `git archive HEAD` 构建；嵌入式 Python 3.12.10（sigstore 校验）+ win_amd64 wheel；PostgreSQL 裁剪 pgAdmin/StackBuilder/文档；VC++ 运行库（微软签名）；内置可分发字体；`SHA256SUMS.txt`、`VERSION.txt`、`licenses/`（含 SBOM）。安装时校验全部文件哈希。客户端电脑无需安装任何运行时。

## 后果与未验证项

- Windows 安装脚本已通过 PowerShell 语法解析与 PSScriptAnalyzer（含 Windows PowerShell 5.1 / Server 2019 兼容性规则）0 告警，但**尚未在真实 Windows 主机或干净 VM 上执行**（LAN-01/02/11 现场项）。
- 双机局域网访问已用“同一主机局域网 IP + 两个独立浏览器上下文”模拟，**不等于两台独立电脑**（LAN-03 现场项）。
